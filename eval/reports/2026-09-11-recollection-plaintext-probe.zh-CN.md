# 纯文本整理诊断：仍无法稳定区分来源和撤回

## 结论

**首三例 gate 未通过，剩余六例不调用。** 简化为纯文本后，模型在两个完整窗口中找回了目标背景，但混入撤回内容和不属于用户的事实；第三个窗口仍返回 `NO_MEMORY`。独立语义复核同意停止。没有写入数据库、改变 Worker 或宣称答题分数提升。

因此不能把之前的问题仅归咎于 `TARGET / CHANGE / BASIS` 格式，也不能把“返回了更多信息”当成修复。

## 方法与边界

输入来自 Task 8 冻结 manifest，完整保留 `frozen-929`、`frozen-374`、`frozen-742` 的 28-Episode payload，包括 USER／AGENT 归属、撤回和全部 refs。只用一个更简单的任务：整理有依据、仍有效的用户背景为第三人称纯文本笔记，不选数据库目标、操作或引用编号，也不学习 Seed。

使用同一冻结运行器与 MiniMax-M2.5 参数，至多两例并发、无客户端重试。只调用 candidate；original request 仅用于生产输入一致性验证。Task 8 是历史参照，**不是本轮新鲜配对对照**。本诊断同时改变了任务与输出要求，不能分离两者的独立作用，更不是模型的严格能力上界。

预写门槛：至少两个完整窗口保留指定背景，且没有实质来源归属或撤回错误，才继续六个人工控制。纯文本故意没有 tagged-text 格式，未使用 Go parser 判它“可落库”，也没有自动补 TARGET／BASIS。

## 已知与未知

目前已知的两个实际失败模式是：

1. Agent 写的传记、建议或泛化说明进入了用户画像。
2. 明确撤回与仍有效背景不能被稳定地分别处理。

纯文本没有解决这两项。它是否提高一般长对话记忆，仍无端到端证据；剩余人工控制未运行，不能声称本轮通过它们。

下一个适合验证的工程方向是**固化输入按来源职责分开**：用户背景整理只获得用户来源视图，Seed 的行为—结果学习仍保留完整行为链。先做隔离诊断，检验该输入组织能否减少混入，同时保留全部用户撤回；不能直接删除 Canonical Episode 的 Agent 内容或改 Seed 资格。这是待验证方向，不是已实现修复。
