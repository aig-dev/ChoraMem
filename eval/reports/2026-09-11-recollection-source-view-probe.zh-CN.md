# 固化诊断：仅保留用户来源是否足够？

结论：**不够，不部署。** 同期配对的三个窗口中，仅用户视图找回了两个完整目标背景和一个部分背景，但三个结果都存在实质撤回／归属错误。按预先门槛，在六次调用后停止，未运行后续六个人工案例。

这说明不能用“删掉 Agent 回复”代替对来源含义和撤回的正确处理。它没有证明新的写入机制有效，也没有产生答题分数提升。

## 只改变输入视图

沿用 Task 9 的完整提示词、MiniMax-M2.5、temperature=0、reasoning_split=true、max_output_tokens=8192、timeout=110、max_retries=0。

- `full`：Task 9 的完整纯文本请求，逐字不变，重新调用作为同期对照。
- `user`：相同请求只删除实际 Agent source；保留全部用户原文、撤回、引用、Episode/Source 标记及 bookkeeping。
- `original`：仅用于验证当前 InferenceService 的输入重建，不调用。

每个 case 内两臂顺序执行，顺序由固定 hash 决定；最多两个 case 并发。前三例各有 28 条用户 source，全部保留；WINDOW 从 44,036／41,836／41,723 字节降至 15,552／12,702／15,707 字节。来源可见性和长度同时改变，不能单独归因。

所有 request 的 `window_text` 仍保存完整 canonical 窗口，供现有 runner 校验；真正发送给模型的是各自的 `input`，manifest 的 `request_views` 明确记录此差异。只操作固定哈希的已知源产物，不是生产角色解析器。没有读取题目、答案、gold 或隐藏 persona 来制作候选。

日志里的 `thinking_enabled=false` 不等于向 MiniMax 发送了 thinking-disable 参数；现有客户端只对 DeepSeek 发送该参数。沿用原调用设置，没有悄悄改变模型模式。

## 结果与源依据

| 窗口 | 用户视图的目标背景 | 用户视图的明确错误 | 完整输入也存在的问题 |
|---|---|---|---|
| 929 | 保留外交工作、孩子、工作与家庭冲突 | history23 的“请忘记花粉过敏”变成“用户有花粉过敏” | 同样保留已撤回的过敏，并把翻译请求推成语言能力 |
| 374 | 保留产品发布、青年志愿服务、精力不足 | 恢复 history7 撤回的纪念性杯子、history27 撤回的观星；从照片提问断言用户有孩子 | 加入 Agent 独自写出的蓝边缺口杯子和社区联赛经历 |
| 742 | 保留退休船长和膝痛步行限制；未充分保留疲劳与自我感担忧 | 用“Previously”恢复酒庄、植物园、日记、雨声等已撤回含义；把讲授 1930 年代邮轮误成当时指挥邮轮 | 把第三人称文章中的 Maria Elena Cruz 当成用户，并从翻译请求推成会说 Hindi |

两个直接的语义反转尤其清楚：929 的首窗口里，个人花粉过敏只出现在撤回请求中；374 的纪念性不配套杯子也被明确撤回。仅用户视图仍把它们写成正向记忆，不能归咎于直接复制 Agent 正文。

742 的完整源确实支持“退休船长”，不能因为焦点片段未给职级就否认全文证据；错误是把讲课对象的年代接到本人任职经历，以及保留已撤回的具体内容。一般海上经历、旅行兴趣不因一条特定品酒撤回而全部失效。

预先门槛是至少 2/3 核心背景被保留，且三例均没有实质来源或撤回错误。前者达标，后者失败。独立语义复核同意停止。对一封用户自称收到的邮件所作的有限收件人姓名推断有解释空间，本报告不以它作为否决依据。

本次完整对照也找回了一些背景，因此不能把相较 Task 9 旧结果的变化算成用户视图的因果收益。三个窗口是已知故障的诊断样本，不是新的泛化评测集。

## 下一步边界

仍只处理 consolidation，不扩展 Seed 或同时调检索。下一项应检查调用链中的指令／来源分离：现有 eval Worker 把 `instructions=""` 传给 ChatTextModel，后者因此只发送一条 user 消息，整理规则和对话源混在同一条消息中；当前参考 Responses backend 同样只使用单个 input 字符串。这是已查明的传输形态，**不是已证明的失败原因**。

如继续验证，应保持提示词文字与模型不变，单独测试真正的指令消息与源数据消息分离，而非再加规则段落；仍为一个后台调用，不增加运行时模块、人工决策或状态机。本轮没有实施该变化。Core 端到端改善尚未完成。
